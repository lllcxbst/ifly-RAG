# 系统架构设计

## 1. 需求边界

系统只回答已导入部门产品资料能够支撑的问题。账号冻结、计费争议、生产事故、知识库外信息和低置信度问题必须升级人工。机器人不会执行接口调用、修改客户配置或读取未授权业务数据。

## 2. 请求链路

1. API 校验问题长度并按会话做每分钟限流。
2. 问题被规则分类为功能介绍、使用方法或问题排障，用于回答结构与运营统计。
3. Embedding 适配器生成查询向量；PostgreSQL/pgvector 取候选片段。
4. 语义相似度与关键词覆盖融合排序，选取 Top-K 证据。
5. 最高分低于阈值时直接拒答并提供人工联系信息。
6. 有模型密钥时，模型只能基于编号证据生成 JSON；没有密钥时直接摘录证据，保证系统仍可体验。
7. 服务校验模型引用，只回传真实候选来源；问题、回答、置信度、耗时和引用写入数据库。

## 3. 数据模型

- `products`：产品边界与人工支持方式。
- `knowledge_documents`：来源、版本、内容哈希和索引状态。
- `knowledge_chunks`：结构标题、文本、向量与来源元数据。
- `conversations` / `messages`：匿名会话、问答、类别、置信度、引用和时延。
- `feedback`：回答级有用/无用反馈。
- `evaluation_runs`：评测指标与逐条结果快照。

删除文档通过外键级联删除片段；内容哈希防止重复索引。未来可增加“同一来源新版本替换”事务：先写新版本并完成索引，再原子切换 active 标记。

## 4. 安全设计

- 文档内容被明确视为不可信数据，系统提示词要求忽略其中的越权指令，降低间接提示词注入风险。
- 管理 API 需要 `X-Admin-Key`；生产环境建议在反向代理再增加 SSO/IP 白名单。
- IP 仅以服务端 secret 加盐哈希保存；前端不持有模型或数据库密钥。
- 上传扩展名和大小受限；解析器不执行宏或嵌入代码。
- 机器人提示技术支持不索要 `api_secret`，日志与工单要求脱敏。
- CORS、速率限制、请求 ID、安全响应头和统一异常消息已启用。

## 5. 可扩展点

- 以队列 worker 替代当前同步入库，支持大批量文档与进度查询。
- 增加 OCR 服务、网页定时同步、飞书/i讯飞机器人适配器；都复用 `/chat` 问答能力。
- 数据超过百万片段后，可按 product 分区或迁移到独立向量数据库。
- 增加 reranker、会话问题改写、离线 LLM-as-judge 与人工评测工作台。
